# 계약금 숫자 정규화 검증 — 2026-11-01

## 목적
기존 공통 10장의 계약금(down_payment)을 신규 평가 필드
contract_amount의 숫자 원화 금액 기준으로 변환할 수 있는지 검증한다.

## 평가 조건
- 대상: 기존 공통 10장
- 계약금 GT 존재: 9건
- 계약금 GT 없음: sample_7.JPG
- 정규화 코드: scripts/eval_gatekeeper/amount_normalizer.py
- 기존 P0~P3 결과 파일은 변경하지 않음
- 해당 결과는 전체 5개 필드의 최종 평가가 아님

## 검증 결과
- 정규화 단위 테스트: 14/14 통과
- 기존 계약금 GT 숫자 변환: 9/9 성공

| 파이프라인 | 정답 | 변환 실패 | 금액 불일치 | 평가 항목 누락 |
|---|---:|---:|---:|---:|
| P0 Raw Full OCR | 6/9 | 2 | 1 | 0 |
| P1 Rectified Full OCR | 5/9 | 3 | 1 | 0 |
| P2 GT ROI OCR | 7/9 | 2 | 0 | 0 |
| P3 Detected ROI OCR | 0/9 | 9 | 0 | 0 |

## 오류 해석
- 변환 실패: OCR 문자열을 유효한 원화 금액으로 해석할 수 없음
- 금액 불일치: 숫자로 변환됐으나 GT 금액과 다름
- 평가 항목 누락: 결과 데이터에 이미지/필드 행 자체가 없음
- P3의 변환 실패 9건에는 빈 문자열 6건과 주변 문장이
  함께 추출된 문자열 3건이 포함됨
- P3의 변환 실패를 전부 OCR 문자 인식 오류로 분류해서는 안 됨

## 정규화 원칙
- deposit과 contract_amount의 최종 목표 표현은 숫자 원화 금액
- 해석 가능한 한글·숫자 금액만 변환
- OCR 오인식을 정답으로 임의 교정하지 않음
- 기존 한글 기준 평가 수치는 역사적 결과로 보존
- 신규 숫자 기준의 전체 EM/CER은 별도로 재계산해야 함
